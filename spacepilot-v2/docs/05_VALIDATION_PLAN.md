# SpacePilot — 30-Day Validation Plan (30 天验证计划)

> 这是**最重要的一份文档**。你现在钱不多，唯一该做的事是：
> **用最少的钱，最快地验证「有没有人真的愿意付钱」。**
> 在验证成立之前，不要写复杂后端、不要买广告、不要招人、不要谈融资。

---

## 核心验证假设（按危险程度排序）
1. **愿付假设**：有房东愿意为"漏损审计"付 $149。← 最危险，先验。
2. **交付假设**：我能真的组织一次升级交付，客户满意。
3. **渠道假设**：我能以可承受成本持续找到这类房东。
4. **收益假设**：升级后房源收益确实提升（长期，用真实数据验证）。

> 规则：**一次只验一个假设**，用能证伪它的最便宜方式。

---

## 第 1 周：验证「有人感兴趣」（成本 ≈ $0）
- [ ] 部署落地页拿到永久网址（见 `00_DEPLOY_PERMANENT_URL.md`）。
- [ ] 选 3 个真实公开房源，手工做"漏损诊断"，发 3 篇公开拆解内容。
- [ ] 进 10 个短租房东社群，真诚给价值，收集"想被免费诊断"的房东。
- **通过标准**：拿到 **≥ 20 个**愿意接受免费诊断的房东联系方式。
- 若拿不到 20 个 → 问题不在产品，在**需求/信息**，先改话术和目标人群。

## 第 2 周：验证「愿意付 $149」（成本 ≈ $0，只需收款链接）
- [ ] 给这 20 人做**免费漏损扫描**（人肉出结果，展示"你每月漏了 $X"）。
- [ ] 向他们提出：「$149 出一份可执行的深度审计 + 回本方案」。
- [ ] 用 Stripe Payment Link / 收款码收钱（**不需要任何后端**）。
- **通过标准（关键闸门）**：**≥ 3 人真实付款 $149**。
- 若 0 人付 → 停下。要么价值没说清，要么这群人不痛。**别继续往下砸钱。**

## 第 3–4 周：验证「交付能成」（成本 = 你的时间）
- [ ] 给付费的人**手工交付**审计报告（用文档模板，不写系统）。
- [ ] 至少推动 **1 人**进入升级提案 → 找 1 家本地供应商手工协调一小项。
- [ ] 完成后做**前后对比**记录，拿到 1 条真实证言 + 1 个公开案例。
- **通过标准**：1 单交付完成 + 客户愿意具名推荐。

---

## 验证之后才做的事（不要提前）
- ✅ 三个假设都过 → 才开始把重复动作产品化（真后端、支付、AI 引擎）。
- ✅ 有 3–5 个真实案例 → 才谈融资 / 找合伙人 / 扩城市。
- ❌ 验证没过之前：不写复杂代码、不投广告、不租办公室、不招人。

---

## 你现在这周就能做的 5 件事
1. 把站点部署上线（Netlify 拖 `out/` 最快，见 `00`）。
2. 建一个 Stripe Payment Link（$149），或准备收款码。
3. 选 3 个房源，写出漏损诊断，发出去。
4. 加 10 个社群，收集 20 个免费诊断需求。
5. 记录：多少人看、多少人要诊断、多少人付款——**用真实数字更新 `03_FINANCIAL_MODEL.md`**。

> 记住：现在这个 App 是**销售道具和信任凭证**，不是收入本身。
> 收入来自"你手工帮真实房东多赚到钱"。先证明这件事能发生。
