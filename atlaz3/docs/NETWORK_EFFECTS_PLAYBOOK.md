# Atlaz — Network Effects Playbook

## The four loops
1. **Data loop (intra-merchant):** each Trade Loop enriches the SKU Passport and ledger →
   the merchant's next decision is faster and better → they run more loops.
2. **Data network (cross-merchant):** anonymized, consented signals improve Supplier Trust
   Scores and Market Demand Signals for everyone → better defaults for all merchants.
3. **Two-sided (supply ↔ demand):** verified suppliers attract merchants; merchant volume
   attracts suppliers (future Factory Portal).
4. **Workflow lock-in:** the more of the loop a merchant runs in Atlaz, the higher the switching
   cost (their history, passports and decisions live here).

## How we seed each loop
- **Data loop:** generous Free tier so the first loop completes; export shareable SKU Passports.
- **Data network:** opt-in consent at onboarding; show merchants the benefit (better trust scores).
- **Two-sided:** seed supplier profiles from mock graph; invite top suppliers to verify (Phase 3).
- **Workflow:** make Atlaz the system of record — ledger, passports, decisions all in one place.

## Defensibility math
Value to each merchant grows with total loops in the network (better signals), while cost per
loop falls (moat data reduces AI/tooling spend). This widens the gap a competitor must close:
they'd need not just features but **equivalent accumulated trade data and trust signals**.

## Guardrails
Network effects must never compromise privacy. All aggregation is anonymized, consented,
purpose-bound and revocable (`DATA_RIGHTS_AND_PRIVACY_BOUNDARIES.md`).
