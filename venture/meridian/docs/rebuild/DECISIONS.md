# 决策记录 (DECISIONS / ADR)

> 每条决策都是"风险调整后的成功概率可行化"原则下的取舍。诚实记录,便于接管者理解为何这样做。

---

## ADR-000 · 关于本轮交付范围的根本决策 (最重要)

**背景**: 收到的《Meridian 2.0 总控指令》要求在"一次执行"内建成 6 个应用、60+ 表、真实全球调研、全套支付/合规/财务/测试/双区域部署。

**事实判断**: 该范围等价于 15-30 人团队 12-18 个月、数千万人民币投入的工作量。任何在单会话内声称"全部极其优秀完成"的输出,必然是伪造 (伪造代码完成度/测试/调研),这**违反指令第 27、31 条本身**。

**决策**: 拒绝伪造。采用指令第 23 条授权的降级策略——
> "若上下文有限,优先交付安全、身份、支付、核心决策闭环和可运行系统,并在 PROGRESS.md 保持精确进度。"

本轮交付 = **P0 全部止血 (真实代码) + Decision-OS 数据模型骨架 + 诚实文档**。其余按真实状态标注,不谎称完成。

**理由**: 对一个资金紧张的创始人,最负责的做法是给能运行、能被接管、不会在尽调中暴雷的真东西,而不是一个看起来宏大、一碰就碎的假系统。

## ADR-001 · 战略定位: 从"AI 算命"升级为"Personal Decision OS"

**决策**: 采纳指令的新定位。命理/八字/紫微**降级为"用户主动选择的文化反思镜头"**,不再作为决定现实结果的权威因果引擎。核心价值改为"帮用户完成一个真实的重大决策 (跳槽/创业/迁居) 并复盘结果"。

**理由**:
1. 纯算命天花板低 (Co-Star 级别月收入仅数万美元) 且监管/伦理风险高;
2. 决策场景决策损失高、付费意愿强、有明确行动、可在 30-180 天后复盘结果 → 能形成"结果校准"的数据飞轮;
3. 保留东方文化作为差异化钩子,但用免责与置信度控制风险。

**代价**: 需要构建决策数据结构 (本轮已落地骨架),比单纯聊天复杂。

## ADR-002 · 本轮暂不迁移到 PostgreSQL monorepo,先在 Workers+D1 上止血

**决策**: 指令要求迁移到 TS monorepo + Postgres + Redis + NestJS。本轮**不做**该迁移,先在现有 Workers+D1 栈上完成 P0 安全修复和数据模型扩展。

**理由**:
1. P0 漏洞 (付费后门、弱密钥) 的危害与技术栈无关,先止血价值最高、耗时最低;
2. 全量迁移是数周工作,若本轮启动必然半途而废,留下一个既非 v1 又非 v2 的破碎状态,违反指令"不得留下破碎状态";
3. D1 是 SQLite 兼容,数据模型设计对 Postgres 迁移友好,不构成锁定。

**后续**: `MIGRATION.md` 记录迁移路径。标记 `NOT_IMPLEMENTED`。

## ADR-003 · 支付: PaymentProvider 抽象 + Mock,真实渠道占位

**决策**: 删除后门,引入 `PaymentProvider` 接口。本轮实现 `MockProvider` (显式标记、生产禁用) + 订单状态机 + 幂等键 + 金额整数存储 (分)。微信/支付宝/Stripe/Apple IAP 留 `REQUIRES_EXTERNAL_CREDENTIALS` 占位。

**理由**: 无商户号/证书时无法真实接入,但可以把"权益只能由验证过的支付事件授予"这一**安全不变量**先建立起来,这才是尽调关注的核心。

---

## ADR-004 · 限流用内存实现,标注需替换

**决策**: 单 Worker 内存滑动窗口限流。标记 `IMPLEMENTED_WITH_INMEMORY_LIMITER`。

**理由**: Workers 多实例下内存限流不全局精确,生产需 Durable Object 或 Redis。但"有基础限流"远好于"零限流",且不阻塞本轮。

---

## ADR-005 · LLM 默认不外发

**决策**: 删除硬编码第三方代理默认。未显式配置且用户未同意时,对话走本地 chart-driven 降级顾问,数据不出境不外发。

**理由**: 隐私默认安全 (privacy by default)。外发第三方必须是显式配置 + 用户知情。
